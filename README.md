# prompt-auditor

> **AI 缺的不是身份标签，是你敢提的要求。**
> 但"往上拉"不是无条件正确——拉错了比不拉更糟。

一个 prompt 审计器：判断你的 prompt 停在哪个能力档位，**该不该升级**，怎么升，以及升级的代价是什么。

---

## 为什么做这个

市面上讲"如何写好 prompt"的内容已经够多了，绝大多数在教你**往上拉**：

- 别只让 AI 干活，告诉它你要什么
- 别只换词，给它高手的框架
- 把名词换成动词，让它跨界想办法

这些话都对。但它们漏掉了最关键的一半：**什么时候不该拉。**

- 让 AI 把 `2026/11/9` 转成 `2026-11-09`，你拉高目标只会得到一段关于时间意义的散文
- 你自己不懂这个领域，拉高之后模型给出的"专业答案"你验不了——**这不是提升质量，是提升欺骗性**
- 目标已经空到「做个好产品」了，再往上拉只会更空，你需要的是往下压

**这个 skill 的第一动作不是改写，是判断该不该改。**

## 四档阶梯

| 档位 | 你要的是什么 | 例 |
|---|---|---|
| **Speed** | 把同一个动作做得更快 | 「你是资深律师，帮我看看这份合同」 |
| **Altitude** | 结果，不是动作 | 「我要和这家供应商重谈条款」 |
| **Depth** | 原始材料 + 顶尖方法，不是二手加工品 | 「顶尖分析师会拉哪些原始数据、建什么模型」 |
| **Range** | 换表征（名词→动词），借跨领域流程 | 「让一群很忙的人看懂前因后果再决策」 |

**Speed 是被否定的基线，不是及格线。** 停在 Speed 意味着你把 AI 当更聪明的聊天框。

## 怎么用

### 作为 Skill 使用

本仓库遵循 `SKILL.md` 规范，可直接用于 Claude Code、Coze 等支持 Agent Skills 的环境：

```bash
git clone https://github.com/<your-name>/prompt-auditor.git
# 复制到你的 skills 目录
cp -r prompt-auditor ~/.claude/skills/
```

之后当你说「帮我看看这个 prompt 怎么改」「为什么 AI 回答很平庸」时，会自动触发审计流程。

### 手动使用

直接把 `SKILL.md` 的内容贴给任意模型，然后附上你要审计的 prompt。

## 审计输出长什么样

```
【当前档位】Speed
【判定依据】"你是一位资深律师，帮我看看这份合同"
            —— 给了角色标签，但没给目标、没给方法、没给验收

【该不该升级】该
【理由】合同审查是开放任务，且用户能判断输出是否可用

【升级方案】
改这一句：你是一位资深律师，帮我看看这份合同
改成：我要和这家供应商重新谈条款。
      1. 找出对方最可能让步的三个点，说明依据
      2. 用记者查证的方式核对背景
      3. 给我一套谈判话术
预期变化：从"评估这份合同"变成"为一次具体谈判做准备"

【代价】
不构成法律意见，正式签署前仍需执业律师过目

【验收标准】
三个让步点每个都有可核实的依据，不是"一般来说"
```

## 一点诚实

本仓库的主张分三类，请区别对待：

| 类型 | 内容 | 置信度 |
|---|---|---|
| 有原始出处 | 四档定义、Felix 原话、现成 prompt、Blender 例子 | 高 |
| 有学术数据 | persona 效果小且不稳定（[arXiv:2408.08631](https://arxiv.org/abs/2408.08631)） | 高 |
| 基于推理 | 边界条件、反例库、六种不该升级的情形 | **中** |

第三类是本仓库原创的部分，也是最需要被质疑的部分。

**我们不声称"这样写效果更好"**——因为还没有对照实验支撑这句话。我们只说：**这样写更接近顶尖从业者的做法**，以及**什么时候连这个都不该做**。
