# 改写示例集

每个案例都标了**该不该升级**。有些案例的正确答案是"别动"——这正是本 skill 和普通 prompt 教程的区别。

---

## 案例 1：简历（Altitude）

**原 prompt**
```
帮我改一下这份简历，让它更专业一些。
```
**当前档位**：Speed
**该不该升级**：该

**改写**
```
我要拿到 XX 公司 XX 岗位的面试。

这份简历是给这个岗位的 HR 看的，他们平均 30 秒过一份。
请先告诉我：这个岗位的招聘方最想确认的三件事是什么？
然后按这三件事重排我的经历，把能证明的往前放，证明不了的删掉。
最后告诉我，按现在的内容，我离拿到面试还差什么。
```
**代价**：目标变具体之后，简历可能不再"通用"——投别的岗位要重做一版。
**验收标准**：能说出"这份简历在回答哪三个问题"，且每个问题都有对应证据。

## 案例 2：代码调试（Altitude + Depth）

**原 prompt**
```
帮我看看这个报错怎么修。
```
**当前档位**：Speed
**该不该升级**：该

**改写**
```
我要让这类崩溃不再发生，不是修这一次。

这是完整崩溃日志（附后）、复现步骤、以及三种系统环境的信息。
请你：
1. 自己复现这个崩溃
2. 判断根因是这一处，还是一类问题
3. 修复，并写一个能捕获这类问题的测试
4. 用测试验证修复，不要自己说"已修复"
```
**代价**：轮次会显著增加，简单 bug 上会浪费时间。
**验收标准**：测试能跑通，且人为注入同类故障时测试会失败。

## 案例 3：数据分析（Depth）

**原 prompt**
```
你是一位资深数据分析专家，帮我算一下这些数据的平均值，画张表。
```
**当前档位**：Speed（persona 只换了措辞）
**该不该升级**：该

**改写**
```
这个领域顶尖的分析师拿到这批数据，会先做什么、用什么工具、建什么模型？

请按这个顺序做：
1. 先说他们会关注哪些指标、为什么，以及我这份数据缺了什么关键字段
2. 用他们会用的方法做完（不要只算平均值）
3. 结论用人话讲，但每个数字都标出它的不确定性
```
**代价**：如果我不懂这个领域，模型给的"顶尖方法"我验不了，可能被看起来很专业的错误说服。
**验收标准**：能指出至少一个"我原来的做法会漏掉的东西"。

## 案例 4：做 PPT（Range）

**原 prompt**
```
帮我做一份关于 Q3 业务的 PPT。
```
**当前档位**：Speed（名词）
**该不该升级**：该

**改写**
```
这份东西要给一群很忙的管理层看，他们要在会上做三个决定。

所以不要先想"PPT 该有哪些页"，先想：
- 他们现在最不确定的是什么？
- 需要看到什么才会下决心？
- 哪些信息可以不给？

按这个思路组织内容，每页只承担一个判断。
```
**代价**：结构可能偏离公司模板习惯，需要自己再套版式。
**验收标准**：每一页都能回答"这页让读者决定什么"。

## 案例 5：合同审查（Range + Depth）

**原 prompt**
```
你是一位资深律师，帮我看看这份合同有没有问题。
```
**当前档位**：Speed（典型戏服 prompt）
**该不该升级**：该

**改写**
```
我要和这家供应商重新谈条款。

请按三步来：
1. 找出对方最可能让步的三个点，并说明依据（行业惯例、条款对谁更不利、替换成本）
2. 用记者查证的方式核对背景：这家公司的履约记录、行业里的常见争议、这条款在类似合同里通常怎么写
3. 最后给我一套谈判话术：先说什么、对方反驳怎么接、底线在哪
```
**代价**：这不构成法律意见，正式签署前仍需执业律师过一遍。
**验收标准**：三个让步点每个都有可核实的依据，不是"一般来说"。

## 案例 6：正则表达式（不该升级）

**原 prompt**
```
写一个正则，匹配 2026-11-09 这种格式的日期。
```
**当前档位**：Speed
**该不该升级**：**不该**

**理由**：封闭任务，有唯一正确答案。拉高目标只会引入歧义。

**唯一值得补的一句**：
```
顺便给我三个能匹配和三个不能匹配的例子。
```
这是加验证，不是加高度。

## 案例 7：论文润色（不该升级，但要加约束）

**原 prompt**
```
帮我润色这段论文。
```
**当前档位**：Speed
**该不该升级**：**不该拉高度，但该加约束**

**理由**：润色是明确的封闭任务，拉高会跑偏。但原 prompt 缺关键约束。

**改写**
```
润色这段，但：
- 不改任何数据和专有名词
- 不改引用标记
- 不增加原文没有的论断
- 保持被动语态（这个期刊的要求）
改完列出你改了哪些地方、为什么。
```
**代价**：无。这是纯约束，不是升级。

## 案例 8：文献综述（Depth）

**原 prompt**
```
帮我写一篇关于点云语义分割的文献综述。
```
**当前档位**：Speed
**该不该升级**：该，但**需要用户先补领域知识**

**改写**
```
先不要写。

1. 列出这个方向近三年最关键的 8 篇工作，说明各自解决了什么、没解决什么
2. 指出它们之间的分歧在哪（哪些结论互相矛盾）
3. 然后告诉我：如果我要写综述，最值得立的角度是什么，为什么别人没这么写过

第 3 步之前先等我确认。
```
**代价**：如果我不熟悉这个方向，第 1 步给的书目我判断不了准不准，可能被虚构的引用骗。
**验收标准**：每篇文献都能在 arXiv 或会议论文库里查到。

## 案例 9：性能优化（Depth，量级）

**原 prompt**
```
帮我优化这个网页的加载速度。
```
**当前档位**：Speed
**该不该升级**：该

**改写**
```
目标是从 3.2 秒降到 200 毫秒以内。

先不要给我优化建议清单。先告诉我：
- 这 3.2 秒里，各阶段分别占多少（DNS、连接、TTFB、下载、解析、渲染）
- 用专业前端工程师的做法，你会先测什么、用什么工具
- 哪个阶段的优化收益最大

然后按这个顺序做，每改一步给我新的测量数据。
```
**代价**：200ms 可能物理上做不到（取决于服务端位置），会得到"做不到"的结论。
**验收标准**：有前后对比的实测数据，不是估算。

## 案例 10：会议纪要（不该升级）

**原 prompt**
```
把这段会议录音转成纪要。
```
**当前档位**：Speed
**该不该升级**：**不该**

**理由**：信息整理任务，瓶颈在转写质量，不在提问方式。

**唯一值得补的**：
```
按"决议 / 待办 / 分歧"三类整理，待办要带责任人和时间。
```
这是结构化输出要求，属于规格约束，不是升级。

---

## 小结：判断口诀

看到一个新 prompt，先问三句：

1. **这件事有唯一正确答案吗？** 有 → 别升级
2. **我能判断输出对不对吗？** 不能 → 别升级，先补知识
3. **我现在要的是结果，还是动作？** 动作 → 可以往上拉一档

三句都过了，再谈怎么改。
